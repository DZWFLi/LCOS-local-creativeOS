# v0.6 交互冻结

## 用户只需理解三样东西

- Canvas：内容与关系
- Work Rail：当前焦点、指令、任务与结果
- 自动过程记录：系统负责 Context、Command、Run、Revision 与 Decision

## 黄金路径

```text
看 → 选 → 说 → 确认
```

### 单文件修改

```text
单击文件 → 输入一句话 → 发送
```

### 多资料修改

```text
框选文件与参考 → 系统推断 Target / Context → 输入 → 发送
```

### 结果确认

```text
结果返回 → 自动 Compare → 接受或继续修改
```

## Work Rail

- 默认常驻，不出现通用聊天空状态。
- 顶部显示当前焦点。
- 中部根据 Workspace、选择、Run 和 Review 自动变化。
- 底部永久保留 Composer。
- Relations、Context、Activity 仍可展开，但不是黄金路径。

## Canvas Scope

- 一个 Project 只有一个 Project Graph。
- Root Canvas 和 Child Canvas 只是不同 Scope。
- Workspace 保存 Scope、Camera、Focus、Layer 与 Context Policy。
- 同一 Artifact 可在多个 Scope 中拥有 ArtifactView。

## 节点正面分类

- 内容节点
- 过程节点
- 确认节点

Context Pack 与 Skill 默认不显示为节点，只有 Pin 后才出现。

## Phase 1 发送确认补充

输入指令后不直接展开复杂配置表单。系统打开一个在 Canvas 可用区域居中的轻量确认面板，只展示：修改要求、修改目标、参考内容和执行方式。面板打开期间 Canvas 锁定，确认后才自动生成 Command / Run / Process Node。
