# AdFrame 视觉规范方案

> 版本：draft-1 | 日期：2026-07-16
> 适用视口：1366×768（基准），1024px（无横向溢出）

---

## 一、四区拼装方案

### 1.1 整体布局

```
┌─────────────────────────────────────────────────────┐
│  Header（固定高度 40px）                              │
│  [Logo/名称]  [案例选择器]  [模式切换]  [全局操作]      │
├──────────┬───────────────────────┬───────────────────┤
│          │                      │                   │
│  左侧    │      中间             │      右侧          │
│  素材/   │      媒体主查看区     │      评测面板       │
│  版本    │                      │                   │
│  面板    │  ┌─────────────────┐ │  ┌───────────────┐ │
│          │  │                 │ │  │ 人工评测       │ │
│  ┌──────┐│  │  媒体内容区域    │ │  │ □ 维度1       │ │
│  │素材1 ││  │  (视频/图片)     │ │  │ □ 维度2       │ │
│  │素材2 ││  │                 │ │  │ □ ...         │ │
│  │素材3 ││  │  时间点标记栏    │ │  ├───────────────┤ │
│  │      ││  │  [●──●──●──●]   │ │  │ AI 评测       │ │
│  │      ││  │                 │ │  │ ▶ 运行        │ │
│  └──────┘│  │  播放控制        │ │  │ ████ 进度     │ │
│          │  └─────────────────┘ │  ├───────────────┤ │
│  ┌──────┐│                      │  │ 综合结论       │ │
│  │版本  ││                      │  │ 一致/冲突      │ │
│  │v1 v2 ││                      │  │ 建议          │ │
│  │v3    ││                      │  └───────────────┘ │
│  └──────┘│                      │                   │
├──────────┴───────────────────────┴───────────────────┤
│  底部 Context / Export 抽屉（可收起，展开时约 160px）   │
│  [生成上下文] [评测摘要] [Markdown 预览] [导出] [Codex] │
└─────────────────────────────────────────────────────┘
```

### 1.2 区域尺寸规范

| 区域 | 1366×768 基准宽度 | 最小宽度 | 最大宽度 | 可调整 |
|------|------------------|---------|---------|--------|
| Header | 全宽 × 40px | - | - | 否（固定） |
| 左侧面板 | 240px | 180px | 320px | 是（拖拽分隔线） |
| 中间查看区 | flex: 1（约 760px） | 480px | - | 自适应 |
| 右侧面板 | 360px | 280px | 440px | 是（拖拽分隔线） |
| 底部抽屉 | 全宽 × 0（收起）/ 160px（展开） | - | 320px | 是（拖拽顶部手柄） |

### 1.3 四区功能划分

#### Header（40px，固定）
- 左：AdFrame 标识 + 案例名称
- 中：案例切换下拉（视频案例 / 图片案例）
- 右：模式切换（评测模式 / 导出模式）+ 全局设置

#### 左侧面板（240px）—— 素材与版本
- **素材列表**：当前案例下的所有素材缩略图列表，当前选中项高亮
- **版本历史**：选中素材的版本列表（v1, v2, v3...），支持单选切换
- **Brief 摘要**：选中素材的 Brief 和生成上下文摘要，可展开查看完整信息
- **面板切换 tab**：素材 / 版本 / Brief（通过顶部小 tab 切换，节省纵向空间）

#### 中间主查看区（flex: 1）—— 媒体焦点
- **媒体内容**：视频播放器或图片查看器，占据区域绝大部分面积
- **时间点标记条**：视频素材的时间轴缩略条，标注已标记的时间点（人工/AI 分别用不同颜色）
- **播放控制**：播放/暂停、逐帧前进/后退、音量、全屏（仅操作必要控件，不展示冗余信息）
- **对比模式切换**：单视图 / 左右对比（原图 vs 生成图，或人工 vs AI 评测结果）

#### 右侧面板（360px）—— 评测
从上到下分为三个子面板（可折叠）：

1. **人工评测**（默认展开）
   - 6 个固定评测维度（商业目标表达 / 平台适配 / 产品融合 / 构图与视觉层级 / 运动连续性 / AI 生成缺陷）
   - 每个维度：评分（1-5）+ 文字备注 + 关联时间点（可选）
   - 底部：提交评测按钮

2. **AI 评测**（默认折叠）
   - 逐个维度模拟 AI 分析进度
   - 每维度显示：评分 + 置信度 + 关键依据
   - "运行 AI 评测" 按钮

3. **综合结论**（人工和 AI 都完成后方可查看）
   - 一致维度（绿色标记）
   - 冲突维度（橙色标记）
   - 综合建议文本
   - "平均分会掩盖冲突"的强调提示

#### 底部抽屉（0→160px，可展开）—— Context / Export
- **Tab 1 — 上下文**：当前评测的完整上下文摘要（Brief + 评测来源 + 时间点汇总）
- **Tab 2 — 导出**：Markdown 预览 + JSON 预览 + 导出按钮
- **Tab 3 — Codex 交接**：结构化交接对象预览 + 一键复制

### 1.4 布局交互规则

- **面板拖拽**：左侧/右侧面板与中间区的分隔线可拖拽调整宽度，拖拽时显示半透明参考线
- **面板折叠**：左侧/右侧面板可一键折叠为图标条（仅显示图标），最大化为中间区腾出空间
- **抽屉展开**：底部抽屉默认收起为 8px 手柄条，hover 或点击展开到 160px
- **响应式断点**：面板宽度调整需要两个最小值约束（左侧 ≥ 180px，右侧 ≥ 280px，中间 ≥ 480px）

## 二、视觉 Tokens（CSS 变量体系）

### 2.1 设计原则

基于 Linear 的 LCH 色彩空间理念和三值主题生成逻辑：

1. **内容先行，UI 退让**：媒体画面是唯一视觉焦点，所有 UI 元素的视觉权重必须低于媒体内容
2. **暗色审片工作台气质**：参考 DaVinci Resolve 的 UI/内容反差——UI 低调统一，内容高对比度
3. **结构被感知而非被看到**：减少可见分隔线，用间距和层次替代边框
4. **避免产品"换皮"感**：不使用大面积渐变色、玻璃拟态、大圆角、投影卡片等装饰性元素

### 2.3 色彩应用规则

| 规则 | 说明 |
|------|------|
| **面板背景不做差异化** | 左侧、右侧、底部抽屉使用相同的 `--color-bg-panel`，仅通过内容区分，不通过颜色区分 |
| **中间区比所有面板暗一个层级** | 中间媒体查看区使用 `--color-bg-workspace`（比面板稍暗），让媒体画面更突出 |
| **区域边界不画线条** | 四区之间用 `--space-1`（4px）的间距自然分隔，底色 `--color-bg-app` 透出形成视觉边界 |
| **仅拖拽手柄显示分隔线** | 面板拖拽分隔线使用 `--color-border-subtle`，hover 时变为 `--color-border-default` |
| **评测维度使用各自专属色** | 6 个评测维度使用 6 种区分色，仅用作小色块标识（左侧 3px 指示条），不作为大面积背景 |
| **人工/AI 冲突视觉区分** | 一致维度使用 `--color-positive`，冲突维度使用 `--color-warning`，仅在结论区的维度卡片上体现 |
| **不使用渐变色** | 任何静态 UI 元素（面板、按钮、标签）不使用渐变背景，避免"产品换皮"感 |

## 三、1024px 收缩策略

### 3.1 目标

在 1024px 视口宽度下，所有内容无横向溢出，核心评测流程可完成。

### 3.2 收缩优先级

按重要性降序收缩/隐藏：

| 优先级 | 策略 | 具体动作 |
|--------|------|---------|
| 1 | 右侧面板自适应收窄 | 360px → 280px（最小宽度），评测维度改用更紧凑的单行布局 |
| 2 | 左侧面板自适应收窄 | 240px → 180px（最小宽度），缩略图尺寸减小，文字截断 |
| 3 | 底部抽屉减少展开高度 | 160px → 120px，减少预览行数 |
| 4 | 评测维度文字精简 | 维度名称从完整短语缩减为关键词（如"商业目标表达"→"商业目标"） |
| 5 | 评分控件紧凑化 | 5 分制评分从独立 radio 改为紧凑滑块或数字输入 |
| 6 | 对比模式限制 | 1024px 下禁用左右对比视图，仅保留单视图或上下对比 |

### 3.3 断点定义

```css
/* 基准桌面：≥1280px */
@media (min-width: 1280px) {
  /* 使用完整的四区布局参数 */
}

/* 小桌面/笔记本：1024px – 1279px */
@media (max-width: 1279px) {
  --panel-left-width: 180px;
  --panel-right-width: 280px;
  --drawer-expanded: 120px;
}

/* 低于 1024px：不做适配（明确不支持移动端/平板） */
@media (max-width: 1023px) {
  /* 显示提示："请在桌面端打开（≥1024px）" */
}
```

### 3.4 关键检查点（1024px 验收）

- [ ] 四区全部可见，无水平滚动条
- [ ] 中间媒体查看区宽度 ≥ 480px（满足视频最小可视尺寸）
- [ ] 所有评测维度在右侧面板可完整操作（无需横向滚动）
- [ ] 左侧面板素材名称至少显示 12 个字符（truncate 后省略号）
- [ ] 底部抽屉按钮不溢出
- [ ] Header 所有元素同一行显示
- [ ] 面板折叠按钮始终可见

## 四、明确不做清单

以下内容**明确不在 AdFrame 的实现范围内**，避免 scope creep：

### 功能层面

- ❌ **真实 AI API 调用**：AI 评测是 mock 数据模拟，不接入 Runway、GPT、Claude 或任何真实模型
- ❌ **用户认证与多用户**：不做登录、注册、权限、角色管理
- ❌ **数据持久化后端**：不做数据库、云存储、后端 API。仅使用 localStorage 保存评测状态
- ❌ **多项目/多工作区**：不做项目切换、工作区管理、团队协作
- ❌ **素材上传与管理**：素材是预设 mock 数据，不做上传、导入、格式转换
- ❌ **视频编辑能力**：不做剪辑、合成、特效、转码。仅播放和逐帧查看
- ❌ **实际导出到外部服务**：Markdown/JSON 导出是前端生成+下载，不调用 Bridge、Codex 或飞书 API
- ❌ **实时协作**：不做 WebSocket、多人光标、同步编辑

### 视觉层面

- ❌ **渐变色背景或大面积装饰**：面板、按钮等不使用渐变，避免"设计感过强"的产品换皮感
- ❌ **玻璃拟态（glassmorphism）**：不使用 backdrop-filter blur、半透明面板
- ❌ **大圆角卡片（> 8px）**：面板和卡片保持 `radius-md`（6px）或 `radius-lg`（8px）
- ❌ **投影用于静态面板**：CSS `box-shadow` 仅用于浮层（工具提示、下拉菜单、模态框）
- ❌ **动画优先于功能**：不使用页面加载动画、入场动效、视差滚动
- ❌ **组件框架（Tailwind / MUI / Ant Design）**：仅使用 `lucide-react` 图标库
- ❌ **自定义字体（除 Inter 和等宽字体外）**：不引入额外字体文件

### 交互层面

- ❌ **复杂拖拽（多面板同时拖拽、面板弹出为独立窗口）**：仅支持分隔线拖拽调整宽度
- ❌ **键盘快捷键全覆盖**：不做全局快捷键系统，仅保留视频播放的标准键盘控制（空格暂停/播放，← → 逐帧）
- ❌ **触摸/移动端适配**：明确仅支持桌面端（≥1024px），不做响应式移动端布局
- ❌ **无障碍完整合规（WCAG AA）**：不做完整的无障碍适配，仅保证基本可操作性

### 架构层面

- ❌ **状态管理库（Redux / Zustand / Jotai）**：使用 React 内置 state + context
- ❌ **路由库（React Router）**：单页应用，不需要前端路由
- ❌ **SSR / SSG**：纯客户端渲染，不需要 Next.js 或类似框架
- ❌ **国际化（i18n）**：仅支持中文界面
- ❌ **A/B 测试或功能开关**：不做特性标志或实验性功能

## 五、实现建议

### 5.1 实现顺序

1. **先搭布局骨架**：CSS Grid 或 Flexbox 实现四区固定布局，用占位色块验证各区域尺寸
2. **注入 CSS 变量**：按照本文 2.2 节完整定义所有变量，确保全局可维护
3. **实现中间媒体查看区**：这是视觉焦点，需要优先验证暗色背景下的视频/图片呈现效果
4. **实现右侧评测面板**：验证 6 维评分控件的交互和语义色使用
5. **实现左侧素材面板**：验证缩略图列表和版本切换
6. **实现底部抽屉**：验证展开/收起动画和导出预览
7. **1024px 收缩适配**：验证窄屏下的布局和交互完整性

### 5.2 关键决策记录

| 决策 | 原因 |
|------|------|
| 使用 CSS Grid 而非 Flexbox 作为主布局 | 四区布局是二维的（行+列），Grid 更直观；Flexbox 用于各区域内部 |
| 不使用 CSS-in-JS | AGENTS.md 指定 plain CSS，保持一致 |
| 6 维评测各使用独立专属色 | 使评测结论区的维度对比一目了然（哪个维度冲突、哪个一致） |
| 底部抽屉默认收起 | 评测主流程不需要看导出，避免分散注意力 |
| 不支持 1024px 以下 | Portfolio demo 场景，演示设备都是桌面端；移动端适配会显著增加开发量 |
