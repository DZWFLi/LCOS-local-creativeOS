# LCOS UI 前端重构 Brief（2026-08-06）

## 0. 背景：为什么现在重构

后端已经按领域本质收口（看 → 判断 → 派活 → 追踪 → 归档，上下文是第一等资产），
但前端仍带着测试期痕迹：信息堆砌、演示用栏目、画布与 Agent 会话互相打架、
导入的上下文没有落到画布上。本次重构原则（用户原话）：

```text
交互要直觉性；所有 GUI 交互简单直接、不超过两步；
没用的全部居于幕后；节点空着就默认不显示，AI 整理后再作为备注补进去；
几个模式只改变节点 GUI 表达，内部逻辑不改 core，通过 skill / mcp 让本地 agent 整理。
```

已知前后端脱节现状（上一轮审计结论）：

1. 画布没有“会话/章节”一等节点形态（NodeKind 无 conversation），导入的对话
   只能手动打开一张扁平 artifact 卡片。
2. 导入后不自动落画布，章节 → 决策/文件/待办挂点不存在。
3. 章节结构化提炼完全外包给 Agent 会话，且只能一章一章点，烧 token。
4. 搜索结果/章节不能直接变成画布参考节点。
5. 大纲与画布双形态（幕布式）没有任何设计。

## 1. Agent 浏览器模式（最高优先级）

现状：

- `?agent=codex` 时画布上多出一张 AgentContextSurface 卡片（“Agent 看到的画布”）。
- 右侧 WorkRail 与本地 Agent 中间的对话框语义冲突。

用户原话：

> “我在 agent 侧边栏浏览器上用一定要顺手，实际上之前把 agent 画布就多加一个
> 卡片是很没用的行为，真正的 agent 画布就是极度简化的，尤其是右侧的边栏可以
> 取消了，因为完全和本地 agent 中间的对话框起冲突。”

目标：

- Agent 模式画布 = 极简画布主体，右侧栏默认不出现。
- 参考 Windows 任务栏/桌面逻辑：状态与操作收敛为**醒目的小按钮**，可收放，
  不占用画布主体。
- 浮层（提案、上下文、节点信息）点击外部即关闭，绝不用卡片常驻。

验收：

- Agent 会话内一眼看到画布全貌，无卡片/边栏遮挡；
- 任何附加信息从“常驻”变为“按需弹出”，两步内可打开/关闭。

## 2. 交互基础：点击/展开/收起

现状：

- 展开与收起的排列“东倒西歪”，没有方向感和视觉引导。
- 点击卡片外部不退出，需要找关闭按钮。

用户原话：

> “现在的 gui 点击逻辑很烂……为什么不能多参考参考成熟的产品 gui 交互，
> 我点击卡片外的区域就是退出呢。”

目标：

- 所有 Popover/Overlay/Dialog：**点击外部即退出**，Esc 退出，取消按钮保留。
- 展开/收起方向一致（如统一向下/向左展开），带遮罩与过渡，不产生位移错乱。
- 任何操作 ≤ 2 步；两步以上的流程必须重构或交给 Agent。

## 3. 信息降噪：测试用/给 AI 看的一律幕后

现状：

- 大量小栏目、状态文本、provenance 信息（provider、runId、版本号等）直接展示。
- 术语做过翻译，但“翻译了对用户也是无效干扰信息”。

用户原话：

> “太多没用的信息展示和小栏目是给测试用的，给 ai 看的……翻译了对用户也是
> 无效干扰信息。”
> “我最烦的就是那个版本数字动一下就跳一下。”

目标：

- 画布上只保留用户决策需要的信息；诊断/开发信息进 debug 模式。
- 版本/编号类信息停止实时闪动，改为稳定、低调、不引人注意的展示（或隐藏）。
- 所有文案过一遍“用户真的需要知道吗”，不需要就删，而不是“翻译得更友好”。

## 4. 预览与打开方式（飞书式）

现状：

- 预览挤在右侧小窗（PreviewSurface），边框丑、占空间。
- 文档/图片/视频没有分场景的打开策略。

用户原话：

> “几个预览模式的 ui 做的简直糟糕的可怜，预览居然还是放成侧边栏小小的，
> 还有丑丑的边框挤占宝贵的预览空间，就应该多学学飞书文档的那种方法，直接
> 占满屏幕……文档要分情况，md 这种就让本地的 agent 那个侧边栏打开给你看，
> 飞书或者网站链接直接浏览器跳转。”

目标：

- 照片/视频/PPT/PDF：双击节点 → **全屏沉浸预览**（占满画布/全屏，无边框）。
- Markdown/纯文本：agent 侧边栏或轻量内联打开。
- 飞书/网页链接类节点：直接跳转浏览器。
- 独立打开（非 agent 内置）时，顶部浏览器式标签/导航栏必须保留（用户反馈
  “单打开时原本的标签页栏目没了”），不允许全屏后丢失导航。

## 5. 节点信息与缩放（AI 可留白）

现状：

- 节点信息“为了加而加”，项目进行中全是干扰。
- 缩放（compact/standard/expanded）展示的是写死的元信息。

用户原话：

> “现在很多信息是为了加而加，我在一个项目进行的时候那些信息全是干扰，
> 而且目前有了 ai，很多信息可以空着，等到我让 ai 整理的时候它补充进去对吧，
> 空着就默认不显示，ai 输入了就可以进行备注。”

目标：

- 字段**默认空则完全不显示**；AI 通过 skill/MCP 整理后作为备注渐进披露。
- 缩放重新设计：放大才显示“AI 已补充的备注/摘要”，而不是堆元信息。
- 展示优先级：内容/缩略图 → 形态图标 → 选择态 → AI 备注 → 状态 → 其他。

## 6. 上下文导入的呈现：达芬奇式流程划分（底部导航）

用户原话：

> “目前有好几种上下文导入后呈现的方式，我希望借此在项目的这一集下对它进行
> 达芬奇式的处理流程划分，导航栏放在下方，可以分成：节点自由整理；该项目
> 上下文/流式线性预览；项目画布空间编辑整理/运行；导出。实际上节点啥的都没
> 有变，就是归纳方式、排序方式、是否自由拖动、空间集合显示多少来判断
> （参考幕布等）。”

目标（四态，底部导航栏）：

```text
1. 节点自由整理   —— 自由画布、可拖动、完整节点集合
2. 项目上下文     —— 流式线性预览（时间线/章节/决策/文件/待办）
3. 画布空间编辑   —— 工作空间/节点集合的组织、运行入口
4. 导出           —— .lcosproj / 文档 / 交接
```

硬约束：

- **节点数据不变**，四态只是归纳方式/排序方式/是否自由拖动/集合显示密度的切换。
- **不改 Core**：整理动作由 skill/MCP 交给本地 Agent 执行。
- 允许提出比四态更巧的方案，但必须保留“一眼看懂这个画布项目什么情况”。
- 工作空间/节点集合如何映射到四态，允许重新设计，但必须与现有节点逻辑复用
  （幕布式：同一层级、两形态切换、无额外规则）。

## 7. 与后端/契约的关系

- 本次不改 Core 领域模型；后端已有能力直接支撑：conversationArtifact、
  pin→decision artifact + 关联边、section annotation（决策/待办/文件）、
  process projection、semantic index（等 Ollama）。
- 需要新增的是**前端呈现适配层**：把 sessions/sections/pinned/annotations
  投影成画布节点集合（复用现有 CanvasNode/edge 管线，不新造一套）。
- Agent 整理动作走既有 MCP 工具（read/annotate/pin/search/semantic）。

## 8. 优先级

```text
P0  Agent 模式简化 + 点击外部关闭 + 信息降噪 + 版本号停止闪动
P1  全屏预览与分场景打开 + 底部导航四态（达芬奇式）
P2  节点缩放重设计 + AI 备注留白机制
CSS 风格统一交给 Figma Make 后续产出，本 brief 不定义视觉细节
```

## 9. 验收清单（交互，不涉及风格）

- [ ] Agent 模式画布无常驻卡片/右栏，附加信息两步内弹出/关闭。
- [ ] 所有浮层点击外部即退出；展开收起有方向与过渡，不位移错乱。
- [ ] 画布上无测试用/给 AI 看的信息；版本数字不闪动。
- [ ] 双击节点：图片/视频/文档全屏沉浸预览；md 走 agent 侧边栏；链接跳浏览器。
- [ ] 单开页面保留顶部标签/导航栏。
- [ ] 节点空字段不显示；AI 备注随缩放渐进披露。
- [ ] 底部四态切换：节点数据不变，只变归纳/排序/拖动/密度。
- [ ] 所有操作 ≤ 2 步；术语对用户是“大白话或不存在”。
