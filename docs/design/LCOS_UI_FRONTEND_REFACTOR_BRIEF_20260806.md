# LCOS UI 前端重构 Brief（2026-08-06）

## 0. 背景：为什么现在重构

后端已经按领域本质收口（看 → 判断 → 派活 → 追踪 → 归档，上下文是第一等资产），
但前端仍带着测试期痕迹：信息堆砌、演示用栏目、画布与 Agent 会话互相打架、
导入的上下文没有落到画布上。本次重构原则（用户原话）：

```text
交互要直觉性；所有 GUI 交互简单直接、不超过两步；
没用的全部居于幕后；节点空着就默认不显示，AI 整理后再作为备注补进去；
几个模式只改变节点 GUI 表达，内部逻辑不改 core，通过 skill / mcp 让本地 agent 整理。
```

已知前后端脱节现状（上一轮审计结论）：

1. 画布没有“会话/章节”一等节点形态（NodeKind 无 conversation），导入的对话
   只能手动打开一张扁平 artifact 卡片。
2. 导入后不自动落画布，章节 → 决策/文件/待办挂点不存在。
3. 章节结构化提炼完全外包给 Agent 会话，且只能一章一章点，烧 token。
4. 搜索结果/章节不能直接变成画布参考节点。
5. 大纲与画布双形态（幕布式）没有任何设计。

## 0.1 全局最高原则：节点级 Agent 操作是横切能力

用户原话（当前轮次）：

> “重点是任意空间，任意阶段，用户可以对任意节点发起他想让本地 agent 做的
> 几大类操作即可。”

规则：

```text
1. 四空间（自由整理/上下文预览/画布编辑运行/导出）只是组织视图，
   不是流程锁。用户在任何空间、任何阶段，都可以对任意节点直接发起
   Agent 操作。
2. Agent 操作按“几大类”组织（如：分类/整理、备注/总结、提炼、生成、
   修改、分析、归档……），具体分类由 UI 结合用户原话设计，本 brief
   不把某一类（尤其“决策”）写成必经步骤。
3. 所有交互不超过两步的优先级仍然成立：选中节点 → 发起 Agent 操作，
   中间不强制经过某个空间或某个步骤。
```

## 1. Agent 浏览器模式（最高优先级）

现状：

- `?agent=codex` 时画布上多出一张 AgentContextSurface 卡片（“Agent 看到的画布”）。
- 右侧 WorkRail 与本地 Agent 中间的对话框语义冲突。

用户原话：

> “我在 agent 侧边栏浏览器上用一定要顺手，实际上之前把 agent 画布就多加一个
> 卡片是很没用的行为，真正的 agent 画布就是极度简化的，尤其是右侧的边栏可以
> 取消了，因为完全和本地 agent 中间的对话框起冲突。”

目标：

- Agent 模式画布 = 极简画布主体，右侧栏默认不出现。
- 参考 Windows 任务栏/桌面逻辑：状态与操作收敛为**醒目的小按钮**，可收放，
  不占用画布主体。
- 浮层（提案、上下文、节点信息）点击外部即关闭，绝不用卡片常驻。

验收：

- Agent 会话内一眼看到画布全貌，无卡片/边栏遮挡；
- 任何附加信息从“常驻”变为“按需弹出”，两步内可打开/关闭。

## 2. 交互基础：点击/展开/收起

现状：

- 展开与收起的排列“东倒西歪”，没有方向感和视觉引导。
- 点击卡片外部不退出，需要找关闭按钮。

用户原话：

> “现在的 gui 点击逻辑很烂……为什么不能多参考参考成熟的产品 gui 交互，
> 我点击卡片外的区域就是退出呢。”

目标：

- 所有 Popover/Overlay/Dialog：**点击外部即退出**，Esc 退出，取消按钮保留。
- 展开/收起方向一致（如统一向下/向左展开），带遮罩与过渡，不产生位移错乱。
- 任何操作 ≤ 2 步；两步以上的流程必须重构或交给 Agent。

## 3. 信息降噪：测试用/给 AI 看的一律幕后

现状：

- 大量小栏目、状态文本、provenance 信息（provider、runId、版本号等）直接展示。
- 术语做过翻译，但“翻译了对用户也是无效干扰信息”。

用户原话：

> “太多没用的信息展示和小栏目是给测试用的，给 ai 看的……翻译了对用户也是
> 无效干扰信息。”
> “我最烦的就是那个版本数字动一下就跳一下。”

目标：

- 画布上只保留用户决策需要的信息；诊断/开发信息进 debug 模式。
- 版本/编号类信息停止实时闪动，改为稳定、低调、不引人注意的展示（或隐藏）。
- 所有文案过一遍“用户真的需要知道吗”，不需要就删，而不是“翻译得更友好”。

## 4. 预览与打开方式（飞书式）

现状：

- 预览挤在右侧小窗（PreviewSurface），边框丑、占空间。
- 文档/图片/视频没有分场景的打开策略。

用户原话：

> “几个预览模式的 ui 做的简直糟糕的可怜，预览居然还是放成侧边栏小小的，
> 还有丑丑的边框挤占宝贵的预览空间，就应该多学学飞书文档的那种方法，直接
> 占满屏幕……文档要分情况，md 这种就让本地的 agent 那个侧边栏打开给你看，
> 飞书或者网站链接直接浏览器跳转。”

目标：

- 照片/视频/PPT/PDF：双击节点 → **全屏沉浸预览**（占满画布/全屏，无边框）。
- Markdown/纯文本：agent 侧边栏或轻量内联打开。
- 飞书/网页链接类节点：直接跳转浏览器。
- 独立打开（非 agent 内置）时，顶部浏览器式标签/导航栏必须保留（用户反馈
  “单打开时原本的标签页栏目没了”），不允许全屏后丢失导航。

## 5. 节点信息与缩放（AI 可留白）

现状：

- 节点信息“为了加而加”，项目进行中全是干扰。
- 缩放（compact/standard/expanded）展示的是写死的元信息。

用户原话：

> “现在很多信息是为了加而加，我在一个项目进行的时候那些信息全是干扰，
> 而且目前有了 ai，很多信息可以空着，等到我让 ai 整理的时候它补充进去对吧，
> 空着就默认不显示，ai 输入了就可以进行备注。”

目标：

- 字段**默认空则完全不显示**；AI 通过 skill/MCP 整理后作为备注渐进披露。
- 缩放重新设计：放大才显示“AI 已补充的备注/摘要”，而不是堆元信息。
- 展示优先级：内容/缩略图 → 形态图标 → 选择态 → AI 备注 → 状态 → 其他。

### 节点着重表达什么（2026-08-06 补充）

用户原话（当前轮次）：

> “决策、备注、阶段总结这些才是该着重表现节点设计。”

规则：

```text
1. 节点视觉重点依次是：决策 → 备注 → 阶段总结（AI 可补充，空则隐藏）
   → 文件身份（缩略图/系统图标/名称/最小状态点）→ 其他元信息。
2. 路径、页数、大小、引用次数、Run ID 等一律进单击详情/Inspector，
   不上节点面（与冻结稿“进入单击详情或 Inspector”一致）。
3. 现有 CanvasNodeVisual 把 provider/runId/parentRunId/时间戳堆在节点面上的
   做法废除；expanded 密度优先展示 AI 备注与阶段总结。
```

### 节点“着重表达什么”的基准（AGENTS.md §8 固化规则，即当时讨论的沉淀）

```text
节点必须区分：Source/Original、Working、Generated/Derived Draft、
Context/Reference、Process/Run、Decision/Checkpoint。
不能只靠颜色，必须结合：形态、图标、边框、位置、文案、状态。
视觉优先级：文件内容/缩略图 → 节点形态与图标 → 当前选择/操作目标
→ 待处理/异常/Running → 分类色 → Workspace 环境色 → 虹彩。
默认密度：当前 Workspace 5–8 个主内容节点；Process 0–3；
非焦点关系减弱；技术配置渐进披露。
```

### 现状核对（全栈包确实没碰的部分）

预览注册器（artifactViewerRegistry）其实已按类型解析：
image / text / pdf / presentation / audio / video / link / fallback，
这是“预览层”的底子。真正缺的是**节点表达层**：

```text
1. CanvasNodeVisual 的 getFileKind 只分 6 类：ppt / pdf / image / md / link / file。
   视频、音频、docx、xlsx、psd、fig、zip 等全部落到通用 FILE 图标 + 格式大字。
2. 网页节点只有 Link2 图标 + 域名占位，没有 favicon、域名卡片、标题描述。
3. pdf / ppt 没有封面帧（首屏缩略图），没有页数封面。
4. 视频没有封面帧/时长，音频没有波形/时长/封面。
5. 文件夹/节点集合没有专属形态（幕布式折叠、集合密度均无）。
6. fallback 预览只显示“文件元数据（只读预览未接入）”，没有引导出路。
7. 导入失败/部分失败没有节点级反馈设计；重复引用、外部文件 stale 无视觉提示。
```

### 节点表达设计目标（按文件类型）

```text
图片    缩略图优先，无图时格式图标 + 标题；全屏沉浸预览
视频    封面帧 + 时长；全屏播放
音频    封面/波形 + 时长；内联播放
PDF/PPT 首屏缩略图 + 页数；全屏翻页预览（DocumentViewer 已有基础）
MD/TXT  轻量文本摘要 + 首段预览；agent 侧边栏打开
Office  图标 + 文件名 + 来源；点击走“由 Agent 解析/转档”或全屏预览
网页    图标/站点色 + 域名 + 标题 + Agent 注入的摘要；点击浏览器跳转
未知格式 诚实占位：图标 + 元数据 + “暂不支持预览，可让 Agent 解析”；
        绝不假装能看
文件夹/集合 专属形态：可折叠、可显示成员数与密度（幕布式）
```

所有文件节点的图标基准统一为“系统/桌面同款图标”，见上方补充规则。

### 用户没明说但必须一起处理的点（补充清单）

## 6. 上下文导入的呈现：达芬奇式流程划分（底部导航）

用户原话：

> “目前有好几种上下文导入后呈现的方式，我希望借此在项目的这一集下对它进行
> 达芬奇式的处理流程划分，导航栏放在下方，可以分成：节点自由整理；该项目
> 上下文/流式线性预览；项目画布空间编辑整理/运行；导出。实际上节点啥的都没
> 有变，就是归纳方式、排序方式、是否自由拖动、空间集合显示多少来判断
> （参考幕布等）。”

目标（四态，底部导航栏）：

```text
1. 节点自由整理   —— 自由画布、可拖动、完整节点集合
2. 项目上下文     —— 流式线性预览（时间线/章节/决策/文件/待办）
3. 画布空间编辑   —— 工作空间/节点集合的组织、运行入口
4. 导出           —— .lcosproj / 文档 / 交接
```

硬约束：

- **节点数据不变**，四态只是归纳方式/排序方式/是否自由拖动/集合显示密度的切换。
- **不改 Core**：整理动作由 skill/MCP 交给本地 Agent 执行。
- 允许提出比四态更巧的方案，但必须保留“一眼看懂这个画布项目什么情况”。
- 工作空间/节点集合如何映射到四态，允许重新设计，但必须与现有节点逻辑复用
  （幕布式：同一层级、两形态切换、无额外规则）。

### 6.1 空间是流水线，不是标签页（2026-08-06 补充）

用户原话（当前轮次）：

> “节点自由整理和上下文导入肯定是多次的，反复的，所以有点像那种 airdrop
> 一样把节点/记录在画布排列好那样子之后能够 drop 到下一个操作空间（gui 上
> 如是，我不清楚这个 core 要不要参与）……这时第一个整理的空间恢复了干净
> 空白方便下一次导入，后面的空间也理解一下这个逻辑。”

设计规则：

```text
1. 四个空间是一条单向流水线：自由整理 → 上下文/流式预览 → 画布空间编辑
   运行 → 导出。每次导入/每批节点 = 一批“货”，按顺序流经各空间。
2. AirDrop 式移交：当前空间把整理好的“工作集”drop 到下一个空间；
   下一个空间以这批节点为输入开始自己的工作。
3. 移交后复位：源空间恢复干净空白工作台，等待下一批导入；不是删除节点，
   只是清掉“当前批的排列现场”。
4. 后续空间同样逻辑：上下文预览审完 → drop 到画布编辑运行 → 导出完 →
   各空间复位，可以再来一批。
```

用户原始意图（原话，UI 以此为准理解，不必照搬下面的建议）：

> “也不是非得有个决策吧，就是类似一大堆零散的文件乱成一堆是不是应该先
> 挨个分类型，分时间，再放进档案柜里。”

> “重点是任意空间，任意阶段，用户可以对任意节点发起他想让本地 agent 做的
> 几大类操作即可。”

> “这个不定死……让 ui 清楚了解我的意图，你只是做建议，让 ui 一定看看你的
> 定义有没有框死，违反我们的第一性原则。”

### 6.2 定义边界：以下均为建议，不是冻结规格

```text
工作集 / drop / 复位 / 四空间语义（见上）只是 Codex 为便于实现给出的建议
方案。UI 必须检查：
1. 是否把“必须经过某一步（尤其决策）”写死了 —— 不允许，用户没有这个要求；
2. 是否违反第一性原则（OS 不制作内容，只负责看/判断/派活/追踪/归档；
   用户只做最少决策）；
3. 是否违背“任意节点任意阶段可直接发起 Agent 操作”。
任何一处框死，UI 有权推翻并替换更贴合意图的表达，只需在实现前说明替换理由。
```

术语（实现时固定，避免歧义）：

```text
工作集 = 当前批次引用的节点集合（视图级引用，不是节点拷贝）
drop   = 把工作集移交给下一个空间（视图状态移交）
复位   = 当前空间清空工作集/排列现场，回到空白工作台
```

Core 参与边界（结论）：

```text
默认纯 GUI 实现，不改 Core：drop 只是视图间的工作集引用移交，
节点/关系/决策/备注/阶段总结仍在项目画布（Core 为唯一真相）。
若后续需要“跨重启找回某批次的处理现场”，用现有 Workspace/Scope 表达批次
（每批 = 一个临时 workspace/scope），不新增核心概念。
整理动作（决策/备注/阶段总结的写入）走 skill/MCP，不直接改 Core 模型。
```

每个空间的工作台语义：

```text
① 节点自由整理   输入：导入（可多次，一堆零散文件）→ 按类型/时间分类、
                 排列归纳 → 放入工作集 → drop ② → 复位
② 项目上下文     输入：工作集 → 流式线性审阅，补充决策/备注/阶段总结
                 （由用户/Agent 按需补充，非必经决策；AI 整理写回节点）
                 → drop ③ → 复位
③ 画布空间编辑运行 输入：工作集 → 排布、发起 Run、审核结果 → drop ④ → 复位
④ 导出           输入：最终工作集 → .lcosproj / 文档 / 交接 → 复位
```

> 以上工作台语义是“建议的默认形态”，受 6.2 边界约束：空间内具体做什么、
> 是否分类、是否备注、是否决策，都由用户在当前节点上按需发起，不设硬流程。

## 7. 与后端/契约的关系

- 本次不改 Core 领域模型；后端已有能力直接支撑：conversationArtifact、
  pin→decision artifact + 关联边、section annotation（决策/待办/文件）、
  process projection、semantic index（等 Ollama）。
- 需要新增的是**前端呈现适配层**：把 sessions/sections/pinned/annotations
  投影成画布节点集合（复用现有 CanvasNode/edge 管线，不新造一套）。
- Agent 整理动作走既有 MCP 工具（read/annotate/pin/search/semantic）。

## 9. 验收清单（交互，不涉及风格）

- [ ] Agent 模式画布无常驻卡片/右栏，附加信息两步内弹出/关闭。
- [ ] 所有浮层点击外部即退出；展开收起有方向与过渡，不位移错乱。
- [ ] 画布上无测试用/给 AI 看的信息；版本数字不闪动。
- [ ] 双击节点：图片/视频/文档全屏沉浸预览；md 走 agent 侧边栏；链接跳浏览器。
- [ ] 单开页面保留顶部标签/导航栏。
- [ ] 节点空字段不显示；AI 备注随缩放渐进披露。
- [ ] 每种文件类型都有明确节点表达：图片/视频/音频/pdf/ppt/md/office/
      网页/未知格式/文件夹集合，不允许“通用文件图标糊弄一切”。
- [ ] 文件节点图标与 Windows 桌面/资源管理器一致，不用格式大字代替。
- [ ] 节点面突出决策/备注/阶段总结，元信息（路径/大小/Run ID）只进详情。
- [ ] 网页节点有站点识别（图标/域名/标题/摘要），点击直接浏览器跳转。
- [ ] 未知格式诚实降级，不假装可预览；导入失败有节点级反馈。
- [ ] 底部四态切换：节点数据不变，只变归纳/排序/拖动/密度。
- [ ] 四空间是流水线：每批可多次导入，整理后 drop 到下游，源空间复位空白。
- [ ] drop/复位只动视图工作集，不删除/移动任何项目节点；重启后项目数据完整。
- [ ] 整理结果（决策/备注/阶段总结）写回节点，走 skill/MCP，不经由 drop。
- [ ] 所有操作 ≤ 2 步；术语对用户是“大白话或不存在”。
