## 三大视图最终语义

### Main

- 一张持续存在的 Project Canvas。
- Scene / Workspace / Collection 是同一项目材料的组织与投影，不创建第二套真相。
- Fence / Region / Workbench / Portal 通过共享 Surface Component contract 工作。
- 拖动使用局部预览、pointer-up 单次提交；Grid Snap 只在临近点阵时按可见主体吸附，不强制紧密重排。

### Context

- 默认进入理解现场，不强迫用户先选 renderer。
- Structure / Evolution / Relationship 是同一 Context membership 的可切换 Lens。
- 当前候选集合来自 Intent、用户 / Agent 显式选择、Saved View、Workspace focus 与启发式推荐；默认推荐不升级为 Project Truth。
- Source 只是来源身份，不能伪造 Conversation History 或 Saved View。

### Workflow

- Workflow 首页是自由行动骨架，不是固定 DAG 页面。
- WorkflowAction 可拥有步骤语义；Skill / Agent / Run 使用真实系统身份。
- Trigger / Gate 等项目角色保持软语义，不升格为全局 Core Node 类型。
- 材料仍是 Project Entity 引用；Review / Checkpoint 通过真实 adapter 投影。
- 布局策略由内容关系推荐并可预览 / 取消，不硬编码成 layered，也不覆盖手工锚点。

## 共享组件与真实性边界

- 22 / 22 Spatial Component Foundation 契约通过。
- `presentation` 组件可由用户创建；`adapter-only` / `planned` 不进入人工创建列表。
- Portal 只绑定稳定工作现场 identity，不复制内容。
- Workbench 只承载已接通的页面 / 工具；不伪造 routine 恢复或 Agent tool runtime。
- Surface Agent Composer 只提交可验证的 Presentation Ops；一项非法则整批 fail closed。
- Ghost / Preview 未确认不持久化，remove projection 不删除 Project Entity。

## 本轮修复的高风险缺陷

1. Main 拖动预览帧已执行后 pointer-up 不提交最终坐标。
2. 300+ 总览裁剪会丢掉超过上限的显式选择。
3. Context 标题层阻断 Lens 按钮点击。
4. schema v0 Context Manifest 缺少 `project.name` 时 Runtime 全链崩溃。
5. Grid Snap 只显示点阵但拖动不再按可见主体吸附。
6. Playwright 把自己启动的 5173 误判成端口占用。

## 诚实保留项

这些项目不包装成 v0.1 已接通能力：

- Context / Workflow 的 Portal 人工创建入口尚未达到 Main 的完整程度。
- Layout Brain 的 `foreground`、`make room`、`deemphasize` 缺少通用 Presentation Ops，当前 fail closed；其余 intent 也只是建议，不是业务规则中心。
- 未完成真实浏览器 100 / 500 / 1000 项的 FPS、输入延迟、内存曲线记录。
- Playwright 有 1 项 relation seed 不具备时的 conditional skip。
- Windows 包体较大：`LCOS.exe` 约 215 MiB，`app.asar` 约 1.9 GiB；可运行但不等于正式发行体积已优化。
- Vite 主 chunk 与 ELK / PDF worker 仍有大体积 warning，需要后续发行优化，不能在 RC 收口中用大规模拆包冒险改动。
