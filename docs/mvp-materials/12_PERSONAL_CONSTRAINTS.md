# 12 — Personal Constraints for MVP Fast Build

## Dz's preferred path

Keep the MVP narrow and honest:

```text
Open Project
→ Canvas shows Brief / Script / Reference / Feedback
→ Reference / Feedback / Note are located
→ FileRecord / Revision identity is visible
→ Restart restores Runtime project
→ Produce handoff/demo pack
```

## Avoid token bonfires

Do not load the entire historical PRD stack unless the next decision needs it.

Prefer:

- current README / AGENTS rules;
- current handoffs;
- focused code search;
- tests that match the slice.

## Working style

- Small commits.
- No automatic push.
- Stop at red-zone boundaries.
- Do not pretend Fixture, Mock, placeholder, or sample notes are Runtime execution.
- Report tests and unresolved items honestly.

## Current biggest product risk

The MVP can look “alive” before Bridge and Preview are real.

So every demo and handoff must distinguish:

- Runtime Project Graph: real.
- FileRecord / Revision identity: real.
- Sample files: real but disposable.
- Preview rendering: not yet real.
- Bridge execution: not connected.
- Watcher / automatic revision: not connected.
