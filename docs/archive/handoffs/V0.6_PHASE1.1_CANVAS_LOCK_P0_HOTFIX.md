# v0.6 Phase 1.1 · Canvas Lock P0 Hotfix

## 失败根因

Phase 1 的确认遮罩把“点击空白关闭”绑定在 `pointerdown`：

```ts
if (event.target === event.currentTarget) onCancel()
```

用户从遮罩区域开始拖动时，面板在手势第一帧就卸载，`runConfirmOpen` 变为 false，Canvas 随即解除锁定。后续 pointer move / wheel 落回 Canvas，同一组手势便能修改 Camera 和节点位置。

锁定清理逻辑本身存在，但遮罩过早关闭让它失去意义。

## 修正

### 1. 遮罩不再承担关闭操作

确认面板和创建面板均取消“点击遮罩关闭”。只有以下显式动作可以关闭：

- Header 关闭按钮；
- 返回 / 取消按钮；
- Esc。

### 2. 遮罩捕获完整指针序列

遮罩空白区域的 pointer down 会取得 pointer capture，并吞掉 move / up / cancel。拖动不会穿透，也不会中途把事件交给 Canvas。

### 3. Canvas 三重锁定

确认面板打开期间：

1. `locked` effect 取消已排队的 drag / wheel animation frame；
2. Canvas 根层 `pointer-events: none`；
3. Canvas pointer down / move / up / wheel 处理器均有 `locked` 硬保护。

即使未来遮罩 DOM 调整，Canvas 也不能在锁定状态下修改几何。

### 4. 保留显式退出

Esc、关闭按钮和“返回修改”仍会正常关闭面板。关闭完成后 Canvas 恢复交互，不改变打开前 Camera 和节点坐标。

## 范围

本热修不修改 Phase 1 的居中计算、Target / Context 推断、执行配置和 Run 创建时机，也不提前进入 Phase 2。
