# v0.6 Phase 1：任务确认与 Canvas 稳定

## 目标

先解决 v0.6 WIP 中最阻塞的交互问题，不扩展后端能力：

- AI 执行配置不再以大型复杂表单悬在 Canvas 中间；
- 发送前只确认“修改要求、目标、参考、执行方式”；
- 确认面板在 Canvas 可用区域中居中；
- 面板打开时 Canvas 完全锁定；
- 锁定时取消已经排队的拖动、缩放、框选和连线帧，避免闪烁；
- 确认后才创建 Command / Run / Process Node。

## 新黄金路径

```text
单击或框选内容
→ 在右侧工作栏输入一句话
→ 打开居中任务确认
→ 开始执行
→ 系统自动创建过程记录
```

普通任务默认只显示：

1. 你想怎么修改；
2. 修改目标；
3. 参考内容；
4. 执行方式：Codex · 保存为新版本。

执行器和输出方式仅位于折叠的“更多设置”中，不再默认展开 Skill、Context Pack、Executor、Output 等内部术语。

## 状态合同

### Work Rail Composer

- `C` 聚焦输入框；
- `Ctrl/Cmd + Enter` 或发送按钮打开任务确认；
- 多个可编辑文件存在歧义时，发送按钮仍可用；
- 用户在居中确认面板中回答“主要修改哪个文件”；
- 默认 Composer 为空，不再用演示长文占据真实空状态。

### RunConfirmDialog

- 使用 Portal，不进入 Canvas transform tree；
- 根据 Dock 与 Work Rail 实际宽度在可用 Canvas 区域居中；
- `Esc` 取消；
- `Ctrl/Cmd + Enter` 确认；
- 内部内容过长时面板内部滚动；
- 不使用 `backdrop-filter`；
- 背景只做静态轻遮罩。

### Canvas Lock

当 `createDialogOpen || runConfirmOpen` 时：

- Canvas `pointer-events: none`；
- 取消待执行的 drag `requestAnimationFrame`；
- 取消待执行的 wheel `requestAnimationFrame`；
- 清空 wheel delta、pan、drag candidate、marquee、link state；
- 暂停 Canvas 节点和边的动画与 transition；
- Dock、Mini-map、Work Rail 由 Portal 遮罩统一阻断。

关闭面板后恢复原 Camera 和节点位置，不重新 Fit、不重建 Canvas。
